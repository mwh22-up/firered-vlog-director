# 导演大脑改造路线

## P0：接入现有剪辑流水线

目标：保护检查成为 FFmpeg 渲染前的硬门禁。

- 对齐家里项目的真实目录和 `edit_plan.json` 字段；
- 生成或补齐 `.vlog-project.json`；
- 将 `guard_project_render()` 接到现有 `pipeline.py render`；
- 用一条已剪辑视频验证正确计划通过、错误计划被阻止。

验收：不修改视频内容时可正常出片；删除一个必留片段后渲染被阻止并生成 QA 报告。

## P1：先支持人工必留节点

目标：用户在 `brief.yaml` 标记的事件自动形成 `locked` 节点。

- 定义 `must_keep` 的文件、时间区间和原因；
- 生成 `work/analysis/moments.json`；
- 自动修正到完整句子或镜头边界；
- 保证用户标记节点覆盖率不低于 95%。

验收：3 至 5 个手工标记节点全部进入成片。

## P2：自动识别重要和好玩节点

目标：融合 Whisper、FireRed/VLM 和音频事件生成 `protected` 节点。

- Whisper 提供词级时间戳和完整句子；
- FireRed/VLM 提供事件、动作、表情和人物反应；
- 音频分析提供笑声、惊呼、能量峰值；
- 多模态证据达到门槛后提升为 `protected`。

验收：人工标注高光召回率优先达到 90%，允许第一版多选但不能明显漏选。

## P3：识别笑点完整上下文

目标：自动建立 `setup → payoff → reaction` 关系。

- 时间边界对齐完整对白、静音点和镜头切换；
- 笑点成员必须成组保留；
- 只保留笑声、删除铺垫或反应时阻止渲染。

验收：测试集中所有笑点均保留原因、爆点和人物反应。

## P4：参考片学习

目标：从用户选择的 Bilibili 参考片提炼可解释导演档案，不训练底层模型。

- 本地下载用户有权分析的视频；
- 输出逐镜头 `reference_analysis.json`；
- 从 3 至 8 个视频归纳 `director_profile.v1.json`；
- 生成计划时记录使用的导演原则；
- 原视频、Cookie 和完整字幕不进入 GitHub。

验收：应用导演档案后，关键节点保留率不下降，人工调整镜头顺序和长度的次数减少。

## P4.5：成片增强

目标：在不改变导演选片的前提下，统一完成逐段画面美化、防抖与连贯、字幕和插画动效。配乐由用户在剪映中完成。

- 从 `edit_plan` 生成版本绑定的 `enhancement_plan`；
- 逐片段执行防抖和重新构图，限制最大裁切；
- 输出保留对白和环境声的无 BGM 画面锁定母版；
- 从 Whisper 词级时间戳生成可读字幕；
- 叠加插画、地图、标注和轻量动效并避开字幕安全区；
- 最终渲染前执行增强计划门禁和视听 QA。

验收：画面无异常裁切，字幕不越界，动效不遮脸、主体、字幕或关键文字，增强前后镜头顺序和时长保持一致。

## P5：偏好反馈学习

目标：从恢复、删除、延长和重排操作中学习个人偏好。

- 保存结构化反馈，不保存敏感媒体；
- 每次更新生成新的导演档案版本；
- 旧版本可回滚并可解释差异；
- 累积足够样本后再评估排序模型或 LoRA。

验收：连续项目中用户恢复镜头的数量持续下降。

## P6：Web 与 Vercel

导演逻辑和本地渲染稳定后，再建设 Vercel 控制台、本地 Worker 配对和任务队列。Vercel 只负责控制面，不运行 FireRed、Whisper 或长视频 FFmpeg 渲染。
